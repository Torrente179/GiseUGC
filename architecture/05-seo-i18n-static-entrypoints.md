# SEO I18N Static Entrypoints

## SEO Build and Runtime

`PageSeo` updates:

- document title
- description and robots
- Open Graph tags
- Twitter tags
- canonical link
- Spanish, English, and x-default hreflang links
- optional route-specific JSON-LD script

The same route content is now present in prerendered HTML. Runtime updates remain
useful for development and same-document state, but crawlers do not need to
execute React to discover the page body or route metadata.

Structured data is moved to the end of `<body>` during prerendering so the
preload scanner reaches visual markup and critical assets earlier without
reducing schema discoverability.

## Page Schema
Service and vertical factories produce WebPage, BreadcrumbList, Service, FAQPage, and VideoObject nodes. Resource pages produce WebPage, BreadcrumbList, Article, and FAQPage. Legal pages produce WebPage and BreadcrumbList. Hub indexes produce WebPage and BreadcrumbList only. They are empty-but-valid shells: site-name title, canonical, hreflang es↔en with x-default on the ES hub, child links, and a contact CTA. Landing Content owns hub headlines and body.

Person schema on the homepages (and the resource Article author node) carries `alternateName` `Gisela.UGC` on Person only. It is not a second Organization, not a keyword, and not a public search target.

Homepage `ProfessionalService` keeps `AggregateRating` 4.8/173 when that graph already exists. Visible Fiverr paragraphs are owned by Landing Content.

## i18n

`src/lib/locale-context.tsx` selects bundled JSON dictionaries from the path.
There is no browser language detector, i18next runtime, or translation request.
Spanish is the default route family; English is under `/en/`.

## Static Entry Shells

Vite builds one input for every localized SEO route. The input list is derived
from `getAllEntrypointPaths()` in `src/lib/locale-path.ts`.
`scripts/prerender.mjs` turns each shell into a complete HTML page and embeds
the typed route data required by its route-family hydrator. Hub indexes use
`src/entry-hub.tsx` / `HubIndexPage` and are distinguished from child landings
before the `/servicios/` and `/services/` prefix match.

The homepage language switcher is a pair of real `<a href>` links to the
current route's ES and EN documents (`/` and `/en/` on the homepages). Head
hreflang remains; the body links exist so crawlers can follow the other locale
without executing the control rail.

`public/sitemap.xml` is generated in prebuild from `PAGE_REGISTRY`. Each
`lastmod` is the latest git date among the family source files and that route's
HTML shell. The six hub indexes are included with x-default on the ES hub.

The canonical Fiverr profile URL is `https://www.fiverr.com/gisela_sm` with no
`?source=gig_page` on schema `sameAs`, hrefs, or llms files.

## Alignment Rule

When adding or renaming a route, update all of these together:

- `src/lib/locale-path.ts`
- the matching data module
- static HTML shell folder/file
- `public/sitemap.xml` (regenerated by `npm run sitemap:generate`)
- hub HTML via `npm run hub:entrypoints` when the route is a hub index
- any entrypoint enrichment data used by the route

Do not hand-add the route to `vite.config.ts`; the registry generates the
Rollup inputs.
